# 資料架構與保存規則

這個 Repository 是公開的。所有原始影音、身分資料、聯絡方式、同意書和代號對照表都不得直接提交。

## 目錄分工

### `data/raw/`

原始資料的說明入口。真正檔案放在私有研究儲存空間，例如：

- 完整遊玩錄影。
- 原始語音。
- 遊戲 log。
- 原始問卷匯出。
- 原始訪談錄音或逐字稿。

Repository 只記錄檔名、私有位置代稱、SHA-256、建立日期與存取限制。

### `data/private/`

極敏感資料的說明入口。真正檔案不能進 Git：

- 參與者姓名與匿名 ID 對照表。
- 聯絡方式。
- 簽名同意書。
- 撤回紀錄。

### `data/processed/`

可提交的去識別處理資料：

- 事件編碼表。
- 匿名問卷結果。
- 條件比較結果。
- 圖表使用的彙整資料。

提交前仍要檢查自由文字、語音內容、檔名和時間資訊是否可能辨識參與者。

### `data/templates/`

固定欄位模板。正式收資料前先複製模板，不直接修改模板本身。

### `data/cases/`

四款遊戲各自的版本、模式、分析與證據入口。

### `data/evidence_index.csv`

所有會被論文引用的證據總表。每個重要主張至少要能連到一個 `evidence_id`。

## ID 規則

### 來源

- `LIT-001`：學術文獻。
- `WEB-001`：官方網頁或更新說明。
- `DOC-001`：內部文件。

### 會談

- `MEET-20260818-01`

### 證據

- `EVD-001`
- `EVD-002`

### 案例

- `CASE-LC`
- `CASE-CW`
- `CASE-REPO`
- `CASE-PEAK`

### 建置版本

- `BUILD-YYYYMMDD-NN`

### 隊伍與參與者

- `T001`：隊伍。
- `T001-P1`：該隊參與者。

姓名對照只能放在私有資料，不得進 Git。

### 場次

`S-YYYYMMDD-T001-A-R1`

- 日期。
- 隊伍 ID。
- 條件 A／B。
- 回合編號。

### 影片

- `REC-S-YYYYMMDD-T001-A-R1`
- `CLIP-YYYYMMDD-001`

### 主張

- `CLM-001`

## 檔名規則

使用 ASCII、數字、連字號或底線；不要把參與者姓名放進檔名。

範例：

```text
S-20260912-T003-B-R1_gameplay.mkv
S-20260912-T003-B-R1_system-log.csv
CLIP-20260912-004_joint-carry.mp4
```

## 原始資料流程

1. 錄製完成後，不修改原始檔。
2. 將原始檔移到私有研究儲存空間。
3. 計算 SHA-256。
4. 在 `video_manifest.csv` 或證據索引登記。
5. 產生工作副本、去識別剪輯或處理資料。
6. 所有剪輯保留原始影片 ID 與時間碼。
7. 論文圖表與口試影片都能一路回查到原始檔。

## SHA-256 範例

Windows PowerShell：

```powershell
Get-FileHash .\S-20260912-T003-B-R1_gameplay.mkv -Algorithm SHA256
```

macOS／Linux：

```bash
sha256sum S-20260912-T003-B-R1_gameplay.mkv
```

## 資料層級

### Level 0｜原始

攝影、錄音、遊戲 log、問卷原始匯出。只讀，不覆寫。

### Level 1｜整理

統一時間、匿名 ID、欄位與格式，但不改研究內容。

### Level 2｜編碼

影片事件、LFCG 判定、訪談主題與錯誤標記。

### Level 3｜分析

條件差、統計摘要、圖表資料。

每一層都要保留上游檔案 ID。Level 2 或 3 出錯時，修正新版本，不覆蓋無紀錄的舊結果。

## 版本記錄

處理檔名加版本：

```text
interdependence_events_v01.csv
interdependence_events_v02.csv
```

在 commit 或文件中寫明：

- 修改日期。
- 修改欄位或列。
- 修改原因。
- 是否需要重跑分析。

## 缺失與排除

任何場次若排除，仍保留在場次總表，並填：

- 排除原因。
- 何時決定。
- 由誰決定。
- 是否在看過結果前預先定義。

不能只刪掉不符合假設的場次。

## 公開影片規則

口試或網路公開的影片要另外確認：

- 參與者是否同意公開播放。
- 語音是否需要變聲、靜音或字幕化。
- 畫面是否出現帳號、好友名單、通知或個人桌面。
- 遊戲素材使用是否符合授權與合理引用範圍。

只同意研究分析，不代表同意公開播放。

## 備份

至少保留：

- 私有主要儲存一份。
- 另一個獨立備份一份。
- GitHub 保存文件、索引、程式與去識別小型資料。

Repository 不能作為原始影片唯一備份。
