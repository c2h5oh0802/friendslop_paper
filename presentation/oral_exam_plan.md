# 口試呈現規劃

狀態：依 2026-08-18 老師建議整理。正式時間、設備與格式尚待確認。

## 老師給的方向

- 以影片為主。
- 第一章不要講太久。
- 聚焦第二章、第三章與實際做出的內容。
- 口試前有實驗很好；來不及也可以沒有完整實驗。

## 報告原則

口試不是把論文從第一頁講到最後一頁。每段內容都要服務三個問題：

1. 我研究什麼問題？
2. 我怎麼分析或測試？
3. 我實際找到或做出了什麼？

## 可依總時間縮放的比例

- 研究問題與範圍：約 10–15%。
- 核心文獻與 LFCG：約 15–20%。
- 方法、資料架構與實驗設計：約 25–30%。
- 案例影片、原型與實際結果：約 35–45%。
- 限制、目前缺口與下一步：約 10%。

正式口試時間確認後再換算分鐘，不先假設固定長度。

## 建議順序

### 1. 一句話交代問題

> 我不是先替 Friendslop 下定義，而是用同一套合作遊戲框架，比較四款被這樣稱呼的作品，再測試部分設計變化是否真的改變玩家互賴。

### 2. 快速交代案例與研究界線

- 四款案例。
- 為何選它們。
- 不研究社群命名因果。
- 不把四款當成全部 Friendslop。

### 3. 只講會用到的 LFCG

用一張圖說明四個面向，接著直接進分析表或影片。不要花大量時間背分類清單。

### 4. 說明研究怎麼留下證據

- 固定版本與設定。
- 每項判定附影片時間碼或來源 ID。
- 觀察與推論分開。
- 主動找反例。
- 原始影片私有保存，公開庫只放索引。

### 5. 播放四案例的關鍵影片

建議依設計問題組織，不依遊戲一款一款介紹：

- 溝通限制如何影響資訊傳遞。
- 物件與體力如何形成分工或共同操作。
- 失去行動後，玩家還能如何參與。
- 原本以為共同但實際出現差異或反例的部分。

### 6. 說明玩家互賴測試

先放基準版與變化版的並排圖，再說：

- 只改哪一個條件。
- 哪些條件固定。
- 什麼行為算互賴事件。
- 如何區分互賴、困難與趣味。

若有先導影片，播放一段完整因果鏈：

> 設計條件 → 玩家請求／共同操作 → 任務結果

### 7. 結尾只回答目前證據能回答的事

- 已完成哪些分析。
- 哪些結果仍是先導。
- 哪些主張還不能成立。
- 口試後下一個最小研究步驟。

## 每段影片的格式

影片開始前顯示 2–3 秒資訊卡：

- `clip_id`
- 遊戲或原型名稱與版本。
- 條件 A／B。
- 要觀察的現象。

影片中：

- 保留必要遊戲聲音。
- 以字幕標記關鍵對話或事件。
- 不用長時間無關遊玩畫面。
- 必要時用游標、框線或慢速重播指出互賴事件。

影片後：

- 一句觀察事實。
- 一句這段能支撐的主張。
- 一句限制或其他解釋。

## 影片選擇標準

優先保留：

- 能看出規則條件的片段。
- 能看出玩家因隊友改變行動的片段。
- 能看出反例或失敗的片段。
- 基準與變化版本可直接對照的片段。

不要只選：

- 最搞笑或最混亂的片段。
- 無法知道版本與條件的片段。
- 只靠旁白才能解釋的片段。
- 只支持假設、不呈現例外的片段。

## 沒有正式實驗時的口試版本

仍可呈現：

1. 四案例的實際分析影片。
2. V-CARRY-01 基準與變化版本。
3. 一段內部先導或功能測試。
4. 互賴事件編碼表。
5. 正式實驗尚缺的招募、倫理或時間條件。

必須清楚標示「方法示範／先導」，不寫成玩家效果已被證明。

## 有正式實驗時的口試版本

增加：

- 隊伍與條件流程圖。
- 操弄檢查結果。
- 每隊 A/B 差異圖。
- 代表性影片與反例影片。
- 客觀、主觀與任務結果是否一致。

## 口試前技術檢查

- [ ] 所有影片可離線播放。
- [ ] 準備常見編碼格式與備用轉檔。
- [ ] 投影片內嵌與外部檔案各有一份。
- [ ] 字幕在投影距離下可讀。
- [ ] 音量一致，不突然過大。
- [ ] 參與者公開播放同意已確認。
- [ ] 畫面沒有帳號、通知或桌面個資。
- [ ] 每段影片在 `video_clip_manifest.csv` 有來源與時間碼。
- [ ] 有無聲備援說明，以防現場音訊故障。

## 尚待老師或正式規定確認

- 口試日期與總時間。
- 是否包含問答時間。
- 現場設備與影片播放限制。
- 是否允許現場操作原型。
- 論文前三章正式格式與交付方式。
